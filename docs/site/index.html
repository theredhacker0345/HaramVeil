What it does

A resilient last line of defense

Unlike DNS blockers that miss embedded media, HaramVeil analyzes what is actually on your screen — and veils it before you see it.

🔍

Layered Detection

Three independent modes — UI-tree scanning, OCR, and visual AI — cooperate so a miss in one is caught by another.

🧠

On-Device AI

NudeNet deep-learning models run locally via ONNX Runtime. Your screen data never leaves the device.

🚫

Anti-Bypass

bcrypt PIN, device-admin uninstall lock, lockdown mode, and a self-closing Safe Window keep protection honest.

🔒

Encrypted Stats

Every block is logged in an SQLCipher database keyed to your PIN hash. No account, no telemetry.

🔋

Battery-Aware

Throttling, frame hashing, and a thermal guard keep scanning efficient. A speed/accuracy slider is built in.

♻️

Always Recovering

Sticky service, boot receiver, alarm + WorkManager health checks, and Samsung keep-alive keep it running.

The Flow

From open app to veiled screen

1

Open an app

The accessibility service receives a window event and submits a throttled scan trigger.

2

Scan the screen

Mode 1 reads the UI tree; even on a clean pass it wakes OCR and the visual AI for eligible apps.

3

Detect a match

Any layer matching a keyword, domain, or explicit image publishes a veil request.

4

Veil & lock

The overlay draws the Veil; lockdown may send you home and log the block encrypted.

The Pipeline

Three modes, one decision

Each layer publishes to a shared event bus. Any match draws the Veil.

1

UI Tree Analysis

Inspects the accessibility node tree of the active app for blocked keywords and domains.

  • Regex + substring blocklists
  • Browser address-bar domains
  • LOW / MEDIUM / HIGH risk tiers
2

Intelligent OCR

Captures an in-memory screen clip and reads text hidden inside images and videos.

  • RapidOCR (FOSS) or ML Kit
  • Catches text Mode 1 can't see
  • Woken only on eligible apps
3

Visual AI

Runs a NudeNet model locally via ONNX Runtime to detect explicit imagery and poses.

  • Mobile (~6MB) / Enhanced (~15MB)
  • YOLOv8 detection decoding
  • Thermal-guarded pacing
// A detection flows like this:
AccessibilityService.onWindowEvent()
  └─ UITreeScanner.scan() // Mode 1
    ├─ match? → DetectionBus.publishVeilRequested(MODE_1)
    └─ wake → Mode1Triggered
        ├─ Mode2Processor (OCR)
        └─ Mode3Processor (Visual AI)
           └─ any hit → VeilOverlayService draws the Veil

Questions

Frequently asked

Will this slow down my phone?
HaramVeil is optimized: visual AI uses hardware acceleration where available, scans are throttled, and a "Battery vs. Protection" pacing control lets you tune frequency. A thermal guard automatically slows visual scanning if inference gets slow.
Is my screen data uploaded?
Never. All processing — OCR, AI inference, and keyword matching — happens strictly on your device. The FOSS production build does not even request the INTERNET permission.
Can I use this with a VPN or DNS blocker?
Yes, and it's recommended. HaramVeil is the "last line of defense" that catches content network-level blockers miss (embedded media, in-app browsers).
What if I forget my PIN?
You can recover access through the security questions you set during onboarding. These are stored locally and encrypted.
How do I temporarily disable it?
Open a "Safe Window" with your PIN. It pauses protection for a chosen duration and auto-resumes afterward so you don't stay unprotected by accident.
Why does it need Accessibility and Overlay?
Accessibility lets HaramVeil read the on-screen UI tree for detection, and the overlay (SYSTEM_ALERT_WINDOW) permission lets it draw the protective Veil over other apps. Both are required for it to function.
